## 0. AI에게 주는 작업 규칙 (꼭 지켜 주세요)

1. **답변은 한국어로만, 짧게.** 길고 복잡한 답은 다시 읽어야 해서 싫어함. 표·목록으로 간단히.
2. **숫자·논문·출처를 지어내지 말 것.** 확인한 것만 쓰고, 확인 못 한 것은 "확인 못 함"이라고 말하기.
3. **근거는 논문이나 공식 수치를 우선.** 우리 영상(12~28개)만으로 만든 기준은 표본이 작아서 보조로만 씀.
4. **치료사 검토는 불가능.** 그걸 해결책으로 제안하지 말 것.
5. **비밀 파일은 절대 올리거나 출력하지 말 것:** `.streamlit/secrets.toml`, `*firebase-adminsdk*.json` (Firebase 서비스 계정 키).
6. **사람 얼굴이 나온 사진·영상은 git에 올리지 말 것** (`videos/`, `*.mp4`, `docs/visuals/*사진*.png`는 .gitignore에 있음). 자세 사진은 얼굴을 흐리게 처리.
7. 코드를 고치면 **테스트를 꼭 돌리기** (아래 4장).
8. 사용자는 재활 전공 대학생. 코드보다 "왜 이렇게 했는지 교수님께 설명할 수 있는가"가 중요.

## 1. 프로젝트 한 줄 요약

**휠체어 사용자의 자세 불균형을 휴대폰 영상으로 재고, 질문으로 자세 문제가 아닌 원인을 걸러낸 뒤, 찾은 문제(키워드)마다 운동을 추천하고 변화를 기록하는 웹앱 (Streamlit).**

### 필요한 이유 (사용자가 정한 3가지)
1. 이미 자세가 틀어진 사람이 많다.
2. 휠체어 사용자는 하체 몫까지 상체로 받으며 이동한다 (어깨·몸통 부담).
3. 휠체어 사용자를 위한 자세 교정 앱이 없다.

### 사용 흐름
1. **홈**: 검사 시작 / 운동 / 기록 버튼, 이번 주 운동 횟수 등 통계, 앱 설명.
2. **검사하기**: ① 질문 5개 → ② 영상 (옆/앞 선택 → 지금 찍기 또는 찍어둔 영상 올리기) → ③ 결과 (먼저 확인할 것, 키워드, 자세 사진, 촬영 점검, 저장).
3. **운동**: 저장된 운동 전부 표시, 내 결과 키워드에 맞는 운동이 위로. 카드 = 이름 + 정식명칭 + 원리 상자(늘이는 근육/강화하는 근육/원리) + 관절 마네킹 + "이것만 주의해요" + 작은 글씨 출처.
4. **기록**: 지난번 | 이번 비교 카드 (거북목은 얼굴 흐린 자세 사진, 어깨·상체는 선 그림) + 전체 추이 그래프.

## 2. 기술 구성

- Python 3.11, **Streamlit 1.41.1**, **MediaPipe 0.10.14** (legacy pose), OpenCV, Firebase Auth/Firestore, plotly, three.js r128 (마네킹).
- 가상환경: `.venv/` (윈도우). 실행: `.venv/Scripts/python.exe -m streamlit run app.py`
- 로그인: Firebase. 비밀값은 `.streamlit/secrets.toml` (예시: `secrets.toml.example`).

## 5. 판정 기준과 근거 (교수님 설명용, 가장 중요)

### 공통 원칙
- 기준값은 **논문의 정상 범위나 단계 기준**을 가져온다.
- 정면 기준 = **건강한 성인 정상 상한(평균 + 2SD) + 사진 측정 오차 여유 약 2°** (사진 측정 최소 변화량 MDC95 약 2.4°).
- 정상값 문헌이 없는 항목은 **측정 최소 변화량보다 큰 값**으로 정한다.
- 우리 영상으로 낸 수치는 "보조 확인"으로만 말한다.

### 키워드별 기준 (config.py `POSTURE_KEYWORDS`)
| 키워드 | 무엇을 재나 | 기준 | 근거 | 측정 신뢰도 |
|---|---|---|---|---|
| 거북목 | 옆 영상, 가만히 3초, 어깨→귀 선과 **수평선** 사이 각 (앱 각도 = 90° − FNTA) | **65° 미만** (FNTA 2단계 이상) | FNTA 단계: 정상 <12°, 1단계 12~25°, 2단계 25~40°, 3단계 ≥40° → 앱 >78 / 65~78 / 50~65 / <50 (Diagnostics 2024, 청소년 145명, 선 자세) | 사진 기반 목 각도 메타분석 ICC 0.90 |
| 한쪽 어깨 처짐 | 앞 영상, 양 어깨 선 기울기 | **5°** | 건강한 성인 100명 1.3 ± 1.0° → 상한 3.3° + 2° | ICC 0.91 |
| 머리 옆 기울기 | 앞 영상, 양 눈 선 기울기 | **7°** | 2.0 ± 1.4° → 상한 4.8° + 2° | ICC 0.51 (보통) |
| 몸통 옆 기울기 | 앞 영상, 골반 중점→어깨 중점 선이 수직에서 기운 각 | **6°** | 1.6 ± 1.2° → 상한 4.0° + 2° | ICC 0.44 (낮음 → 참고용으로만 표시) |
| 밀 때 상체 무너짐 | 옆 영상, 밀 때 상체가 가만히 있을 때보다 더 숙여진 각 | **10.6° 이상 + 피로 답변** | 휠체어 경험자 7.37 ± 3.26° 평균 + 1SD (Symonds 2016) · 피로 → 상체 숙여 밀기 → 부상 위험 (Rodgers 2000) | — |
| 권장과 다른 미는 패턴 | 손이 돌아오는 길 | 반원형이 아니면 | 척수손상 의학 가이드라인 (Consortium for Spinal Cord Medicine 2005) | 판별 정확도: 정답 붙은 영상 16개 중 14개 맞힘 (88%) |
| 밀 때 한쪽 처짐 | 밀 때 어깨 기울기 − 가만히 있을 때 | **3°** | 정상값 문헌 없음 → 측정 최소 변화량(약 2.4°)보다 큰 값 | — |

### 한계 (먼저 밝히기)
- 정상값 연구는 대부분 **선 자세**. 앉은 휠체어 사용자 정상값은 못 찾음. 앉으면 CVA 약 2° 작아짐 (47.8 vs 50.0°).
- 휠체어에 앉은 척수손상 선수 28명의 귀–C7 선과 수직선 각이 46~47°(남 46.4, 여 47.2) → CVA 약 43~44°로 일반 정상 기준(48~50°)보다 작음 = **앉은 휠체어 사용자는 대부분 거북목 범위로 나오는 게 문헌과 맞음** (Pooryamanesh 2024).
- MediaPipe 어깨 점은 논문의 어깨뼈 끝(acromion)과 같지 않음. MediaPipe 각도를 C7·acromion 기준과 직접 비교한 연구는 못 찾음 → 다음 검증 과제.
- 우리 영상 12개 보조 확인: 가만히 있는 동안 흔들림 중앙값 2.2°, 앞·뒤 절반 차이 95% 범위 ±7° → 지난번과 비교할 때 6° 넘게 달라져야 변화로 봄 (`trunk_change_min_detectable_deg` 6°).
- ICC 0.9는 "정확도 90%"가 아니라 "측정값 차이의 90%가 진짜 자세 차이(10%는 오차)" 뜻. 0.9 이상 = 매우 좋음 (Koo & Li 2016).

### 질문 5개 (카메라로 못 보는 것)
상체 조절(혼자 일으킴), 통증 0~10 (NRS, 1~3 가벼움/4~6 중간/7~10 심함, 2점 이상 변화가 의미 있음), 미는 법 배운 적, 휠체어 맞춤 조정 시기, 5분 연속 밀기 피로. → 자세 문제가 아닌 원인을 거르거나(예: 상체 조절 안 되면 '밀 때 상체 무너짐' 제외) 안내를 붙임.

### 촬영 품질 점검 (분석 후 "촬영 점검" 상자)
- 거리(몸 크기), 밝기·역광, 관절 보임 비율, 처음 3초 가만히, 미는 횟수, **찍은 방향**(어깨 너비÷몸통 길이: 옆 0.4 초과면 비스듬함, 앞 0.5 미만이면 옆으로 돔).
- **올린 영상**: 배경 세로선으로 기울기(3° 이상 경고, 실제보다 1~3° 크게 읽음 → "약 N°"), 배경 움직임으로 흔들림(흔들린 프레임 20% 이상 경고). 흔들리면 기울기 판단 건너뜀. 정면에서 기울기 경고가 뜨면 "어깨 값이 틀어졌을 수 있다" 안내.
- 시험: 정상 영상 28개 잘못된 경고 0개, 일부러 3/5/8° 돌리거나 흔든 영상은 모두 경고. (가짜로 만든 영상이라 실제 잘못 찍은 영상으로는 미확인)
- **사이트에서 찍을 때**: 휴대폰 센서로 수평선(2° 이내 초록), 녹화 중 흔들림 경고, 앞 영상은 기울기만큼 각도 보정.

## 6. 운동 (data/exercises.json) — 키워드 → 운동

| 이름 (정식명칭) | 키워드 | 늘이는/강화 근육 | 출처 |
|---|---|---|---|
| 휠체어 반원 밀기 (반원형 추진 기법) | 미는 패턴, 밀 때 한쪽 처짐 | — | 척수손상 가이드라인 2005 |
| 팔 W 만들기 (W 견갑 후인 스트레칭) | 거북목 | 늘이기 대흉근 / 강화 중·하부 승모근·능형근 | Sheikhhoseini 2018 메타분석 |
| 10초 거북목 리셋 (경추 정렬 교정) | 거북목 | 흉쇄유돌근·사각근 | 〃 |
| 목 앞쪽 늘이기 (전경부 스트레칭) | 거북목 | 흉쇄유돌근·사각근 | 〃 |
| 어깨 높이 맞추기 (광배근 측면 신장) | 어깨 처짐 | 낮은 쪽 광배근·옆구리 | Byun 2014 |
| 뭉친 목·어깨 풀기 (상부승모근·견갑거근 스트레칭) | 머리 기울기, 어깨 처짐 | 높은 쪽 상부승모근·견갑거근 | 임상에서 흔히 쓰는 스트레칭 |
| 옆구리 늘이기 (좌위 체간 측굴 스트레칭) | 몸통 옆 기울기 | 기운 쪽 요방형근·복사근 | Romano 2024 Cochrane |

- 운동은 사용자가 유튜브에서 직접 골라 옴 → 그 영상을 보고 **관절 마네킹 동작을 손으로 만듦** (`tools/make_motions.py`, 단계 자막, 팔·다리 길이 고정 IK). 휠체어 미는 법은 가이드라인 보고 만듦.
- 사용자 의견: "거북목에 턱 당기기·가슴 스트레칭만으론 안 된다" → 그런 일반 운동 5개는 삭제함.

## 8. 남은 일 (우선순위)

1. **정식 배포** (Streamlit Community Cloud) — 발표 시연용 고정 주소. GitHub 저장소 필요 (아직 커밋 없음: git 사용자 이름·이메일 미설정). secrets는 사이트 설정에 따로 입력.
2. **발표 자료 반영**: 판정 기준 표 + 신뢰도(ICC) + 촬영 점검 + 사진 기록 비교 화면. 판넬 파일: `docs/KY-FESTA_판넬_휠런스*.pptx`. 사용자 발표 파트는 "02 프로젝트 내용".
3. 휴대폰에서 흔들림 경고·분석 끝까지 확인.
4. (선택) 정면 어깨·밀 때 상체도 자세 사진으로 보여주기 (지금은 선 그림).
5. 밀 때 상체 무너짐 판정 변경 **적용 완료(2026-11-11)**: 10.6° 이상 + 피로 질문 "little/tired"일 때만 키워드 ("지쳐서 상체로 밀고 있어요… 어깨 부담"). 피로 없으면 숫자만. 근거: Rodgers 2000 JRRD(피로 → 상체 숙여 밀기 → 팔·어깨 부상 위험), Rodgers 1994 Arch Phys Med Rehabil 75:85-93.
6. 거북목 안내는 단계별로 적용 완료(2026-11-11): 2단계 "경향·권장"(운동 뒤로), 3단계 "먼저 추천"(맨 앞), 1단계 표시 안 함. `keywords.py`의 `Keyword.weight`.
7. 근거 약점 (비판 검토 결과): ① ICC 0.9는 사람이 점 찍는 사진 측정 신뢰도이지 우리 앱(MediaPipe 자동)의 신뢰도가 아님 → 같은 사람 2~3번 촬영으로 앱 재검사 신뢰도를 재는 게 가장 효과 큼. ② 정면 +2° 여유는 CVA 연구의 MDC를 빌린 값. ③ 운동 근거는 일반인 연구 기반(휠체어 대상은 Pooryamanesh 2024 하나). ④ "이것만 주의해요" 문구·마네킹 동작은 출처 없이 만든 것. ⑤ 질문 거르기 규칙과 '함께 나타남' 연결은 설계 논리(검증 안 됨).
6. (검증 과제) 일부러 거북목/바른 자세로 찍은 영상으로 앱이 구분하는지, C7 스티커 사진과 앱 각도 비교 (앱에 디버그 모드 "C7 찍기" 도구 있음).

## 9. 지금까지의 주요 결정 (다시 묻지 말 것)

- 재검사 주기 고정(4주) 없음 — 사용자가 원할 때 다시 검사.
